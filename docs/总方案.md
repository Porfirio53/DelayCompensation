# TiRex-2 车辆状态延迟补偿系统：研究方案调整与交接

本项目基于预训练 TiRex-2 的当前实现，研究远程驾驶场景下的车辆状态延迟补偿。前期使用 Comma2k19 车辆速度数据，在 175 ms 和 300 ms 固定通信延迟下开展实验，已验证当前版 TiRex 的短时预测能力。研究重点应从进一步降低预测误差，转向如何使其真正适用于存在动态通信延迟和计算耗时的在线系统。

**现决定暂缓原计划的观测年龄条件化残差 Adapter，将后续研究重点调整为三个方面：时延确定、计算时延补偿、流式输入输出。** Adapter 可以保留为后续精度优化方向，但不再作为当前核心研究任务。新的总体目标是保留 TiRex 的预训练预测能力，在外部构建时间感知、动态预测跨度调整和异步在线运行机制，实现车辆状态的连续估计。

**第一，解决真实环境中的时延确定问题。** 当前实验的 175/300 ms 延迟都是预先设定的，实际网络中则会出现时变延迟、抖动、丢包和乱序。研究应重点利用发送端源时间戳、接收端时间戳及时间同步机制，实时确定最新有效观测的年龄（Age of Information，AoI），即 \(a(q)=q-s_{\mathrm{last}}\)。相比单纯估计网络 RTT，观测年龄直接决定 TiRex 需要向未来预测多远。现有数据准备模块已经实现到达过程模拟、时间戳管理和接收端可见历史构造，后续应在此基础上增加真实时间同步、动态观测年龄计算及时间测量误差实验。

**第二，将模型计算时延纳入预测补偿。** 现有实验只补偿通信延迟，实际上 TiRex 的推理计算也会使结果交付时刻进一步滞后。例如观测年龄为 175 ms、计算耗时为 100 ms 时，模型应预测最新观测之后约 275 ms 的状态，而不是仅预测 175 ms。有效预测跨度定义为 \(h_{\mathrm{eff}}=a_{\mathrm{obs}}+c_{\mathrm{queue}}+c_{\mathrm{infer}}\)。后续需要首先测量 GPU batch=1 的真实端到端推理耗时及 P50/P95/P99，再建立计算耗时估计机制，使模型提前生成覆盖预计交付时刻的未来轨迹，并在结果完成后根据实际时间选择对应预测值。评价重点应由调用开始时刻的预测误差扩展到结果交付时刻的预测误差。

**第三，实现流式输入、异步推理和连续输出。** 目前 TiRex 开源接口每次预测都需要重新计算历史上下文，无法直接进行真正的增量推理，而车辆数据每 25 ms 就会产生一个新采样点。因此，应首先建立持续接收数据、维护时间戳与历史缓冲区、异步调用 TiRex、缓存未来预测轨迹并高频发布状态估计的在线系统。可以采用双速率架构：TiRex 以实际计算能力允许的频率更新预测轨迹，在两次完整推理之间通过已有预测轨迹或轻量更新机制持续输出状态，争取实现 40 Hz 状态发布，同时避免推理任务排队积压。

在外部流式系统运行稳定后，再进一步研究 TiRex 内部的增量计算与状态复用。重点包括 xLSTM 隐藏状态缓存、32 点 patch 对应的 800 ms 更新粒度、未满 patch 的处理、归一化基准变化和迟到数据导致的状态更新等。此前提出的短预测裁剪、上下文优化和预处理加速仍然保留，但主要服务于降低单次推理耗时与在线计算负担，而不再作为独立的精度优化主线。

**调整后的实施顺序为：固定当前 TiRex 基线并完成单请求性能测试 → 实现真实时间戳与动态观测年龄确定 → 实现计算时延感知的预测跨度调整 → 构建异步流式输入输出系统 → 研究状态复用及进一步推理加速。** 各阶段分别评价预测精度、观测年龄误差、交付时刻误差、单请求耗时、输出更新频率，以及动态延迟和通信异常下的表现。开发、联调与阶段验收仅使用当前版 TiRex，权限约束见 [AGENTS.md](../AGENTS.md)；时延确定先独立验证测量准确性，不要求加载预测模型。

最终研究方向暂定为**“面向动态通信与计算延迟的 TiRex-2 在线车辆状态预测补偿系统”**。核心贡献不再依赖额外训练一个残差网络，而是研究如何在真实时变通信和有限计算资源条件下，使 TiRex 根据实际信息年龄确定预测目标，补偿推理带来的额外时间滞后，并持续输出与当前时刻对齐的车辆状态估计。
